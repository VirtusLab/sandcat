# Split mitmproxy Volume — Design (issue #25)

## Goal

Stop exposing the mitmproxy CA private key (and other private-by-design files) to the agent container. Today a single `mitmproxy-config` Docker volume is mounted read-only to the agent container at `/mitmproxy-config/`, and it contains `mitmproxy-ca.pem` (CA cert + private key), `mitmproxy-ca.p12`, and `wireguard.conf` (WireGuard private keys). Because uid 1000 in the mitmproxy image (owner of those files, mode 0600) aliases to `vscode` in the agent container, the agent can read them despite the RO mount. Confirmed live on 2026-08-12.

Split into two volumes with clear public/private boundary:

- **`mitmproxy-config`** (existing name, semantics narrowed to "private") — CA private key + PKCS12 with priv, WireGuard config, DH params, mitmproxy internal files. Mounted to mitmproxy (writable) and wg-client (RO, trusted, needs `wireguard.conf`). **Never mounted to agent.**
- **`mitmproxy-public`** (new) — files the agent legitimately needs: public CA cert, `sandcat.env`, `cursor-cli-config.json`. Mounted writable to mitmproxy, RO to agent at `/mitmproxy-config/` (unchanged agent-side path — app-init.sh doesn't change).

## File-to-volume mapping

| File | Reason | Volume | mitmproxy | wg-client | agent |
|---|---|---|---|---|---|
| `mitmproxy-ca.pem` | CA cert + priv key | `mitmproxy-config` | rw | — | — |
| `mitmproxy-ca.p12` | PKCS12 w/ priv key | `mitmproxy-config` | rw | — | — |
| `mitmproxy-ca-cert.pem` | CA cert only | `mitmproxy-public` | rw | — | ro |
| `mitmproxy-ca-cert.p12`, `.cer` | Public cert variants, mitmproxy internal | `mitmproxy-config` | rw | — | — |
| `mitmproxy-dhparam.pem` | Public DH params, mitmproxy internal | `mitmproxy-config` | rw | — | — |
| `wireguard.conf` | WireGuard priv keys | `mitmproxy-config` | rw | ro | — |
| `dns.conf` | Public DNS list, needed by wg-client | `mitmproxy-config` | rw | ro | — |
| `extra_hosts` | Public host mappings, needed by wg-client | `mitmproxy-config` | rw | ro | — |
| `sandcat.env` | Placeholders + env for agent | `mitmproxy-public` | rw | — | ro |
| `cursor-cli-config.json` | Cursor CLI config, agent-consumed | `mitmproxy-public` | rw | — | ro |

Rationale for keeping `dns.conf` / `extra_hosts` in the private volume: wg-client needs them (trusted), agent doesn't (its network namespace is wg-client's, so `/etc/hosts` and `/etc/resolv.conf` are applied by wg-client and inherited).

Rationale for putting public CA cert (`mitmproxy-ca-cert.pem`) in `mitmproxy-public`: this is the ONLY file agent needs from mitmproxy's cert dir, and it's fully public.

## Mounts

**mitmproxy** (`compose-proxy.yml`):
```yaml
volumes:
  - mitmproxy-config:/home/mitmproxy/.mitmproxy   # writable, all files land here first
  - mitmproxy-public:/mitmproxy-public             # writable, addon writes agent-facing files here directly
```

**wg-client** (`compose-proxy.yml`):
```yaml
volumes:
  - mitmproxy-config:/mitmproxy-config:ro         # unchanged — needs wireguard.conf + dns.conf + extra_hosts
```

**agent** (`compose-all.yml`):
```yaml
volumes:
  - mitmproxy-public:/mitmproxy-config:ro         # CHANGED — was mitmproxy-config, now mitmproxy-public (agent path unchanged)
```

## Addon changes — write dynamic files to public volume

`cli/templates/devcontainer/sandcat/scripts/mitmproxy_addon_common.py` currently has:

```python
SANDCAT_ENV_PATH = "/home/mitmproxy/.mitmproxy/sandcat.env"
CURSOR_CLI_CONFIG_PATH = "/home/mitmproxy/.mitmproxy/cursor-cli-config.json"
SANDCAT_DNS_CONF_PATH = "/home/mitmproxy/.mitmproxy/dns.conf"
EXTRA_HOSTS_PATH = "/home/mitmproxy/.mitmproxy/extra_hosts"
```

New:

```python
# Agent-visible files go to the mitmproxy-public volume (mounted RO in the
# agent container). wg-client-only files stay in .mitmproxy — see issue #25.
SANDCAT_ENV_PATH = "/mitmproxy-public/sandcat.env"
CURSOR_CLI_CONFIG_PATH = "/mitmproxy-public/cursor-cli-config.json"
SANDCAT_DNS_CONF_PATH = "/home/mitmproxy/.mitmproxy/dns.conf"      # unchanged — wg-client reads it
EXTRA_HOSTS_PATH = "/home/mitmproxy/.mitmproxy/extra_hosts"        # unchanged — wg-client reads it
```

## Seeding the public CA cert

`mitmproxy-ca-cert.pem` is generated by mitmproxy inside `.mitmproxy/` on first startup. It needs to be copied to `/mitmproxy-public/` so the agent can read it.

Simplest: extend the mitmproxy addon's `load()` (or a running() hook) to copy on startup:

```python
def _seed_public_ca_cert(self):
    """Copy the public CA cert into the agent-facing volume."""
    src = "/home/mitmproxy/.mitmproxy/mitmproxy-ca-cert.pem"
    dst = "/mitmproxy-public/mitmproxy-ca-cert.pem"
    # mitmproxy generates the CA lazily; wait briefly if it isn't there yet
    for _ in range(10):
        if os.path.isfile(src):
            shutil.copy(src, dst)
            ctx.log.info(f"Seeded public CA cert to {dst}")
            return
        time.sleep(1)
    ctx.log.warn(f"CA cert not present at {src} after 10s — agent may see no cert")
```

Called from `load()` (or an appropriate lifecycle hook). Idempotent — re-copy on every restart is fine.

```yaml
test: ["CMD", "sh", "-c", "test -f /home/mitmproxy/.mitmproxy/wireguard.conf && test -f /home/mitmproxy/.mitmproxy/mitmproxy-ca-cert.pem && test -f /home/mitmproxy/.mitmproxy/dns.conf"]
```

Updated:

```yaml
test: ["CMD", "sh", "-c", "test -f /home/mitmproxy/.mitmproxy/wireguard.conf && test -f /mitmproxy-public/mitmproxy-ca-cert.pem && test -f /home/mitmproxy/.mitmproxy/dns.conf"]
```

The healthcheck now gates on the public CA cert being SEEDED to the public volume, guaranteeing the agent (which starts only after wg-client healthy → mitmproxy healthy) finds it.

## Upgrade path

For existing projects with a live `mitmproxy-config` volume:

- Docker will create the new `mitmproxy-public` volume automatically on next `docker compose up`.
- Addon seeds public files into it via `load()`.
- Old files in `mitmproxy-config` (sandcat.env, etc.) become stale — inaccessible from agent (removed mount) and unused by mitmproxy (addon writes fresh copies to public volume now). Not a leak.
- No manual `docker compose down -v` required.

## Security model — what agent CAN and CANNOT see after fix

**Cannot** (was accessible before this fix):
- `mitmproxy-ca.pem` — CA private key ✓ closed
- `mitmproxy-ca.p12` — PKCS12 with private key ✓ closed
- `wireguard.conf` — WireGuard private keys ✓ closed
- `mitmproxy-dhparam.pem` — DH params ✓ closed (though public, no need)

**Can** (unchanged from before):
- `mitmproxy-ca-cert.pem` — public CA cert (needed for TLS trust)
- `sandcat.env` — env + placeholders (agent reads these)
- `cursor-cli-config.json` — cursor CLI config (agent reads for cursor agent)

## Testing

- **bats**: assert compose files list both volumes, agent mount points at `mitmproxy-public`, wg-client mount unchanged.
- **Integration**:
  1. `sandcat init` any agent, full stack up.
  2. From agent: `ls /mitmproxy-config/` — only public files listed.
  3. From agent: `cat /mitmproxy-config/mitmproxy-ca.pem 2>&1` — must FAIL (No such file or directory).
  4. From agent: `curl -sI https://api.github.com/` — must SUCCEED (CA still trusted).
  5. From agent: `env | grep COPILOT_GITHUB_TOKEN` or equivalent — env var still set (sandcat.env reached agent).
  6. Wg-client: check /etc/hosts has extra_hosts entries applied (they still reach wg-client via unchanged mount).

## Global Constraints

- Existing `mitmproxy-config` volume keeps its name — only its scope narrows and the agent-side mount is removed.
- New volume named `mitmproxy-public`.
- Agent-side path stays `/mitmproxy-config/` — no changes to `app-init.sh`. This keeps the fix invisible from every consumer that reads `/mitmproxy-config/mitmproxy-ca-cert.pem` etc.
- All four agents (claude/cursor/codex/copilot) work identically post-fix — no per-agent branches.
- No new dependencies. Uses Python `shutil.copy` (stdlib) in addon.
- Healthcheck gates on public volume population — agent depends_on wg-client depends_on mitmproxy(healthy), so agent starts only after public files exist.
